# CommitFit

Daily **calorie / protein** and **workout** tracker, deployed serverless on AWS at `https://devopsminilab.site`.

| Layer | Folder | Role |
|-------|--------|------|
| IaC | `*.tf` | Provisions all AWS infrastructure |
| Frontend | `www/` | Nutrition + Workout SPA |
| Backend | `lambda/` | HTTP API (Node.js 20) |
| Widget | `Scriptable/` | iPhone home-screen widget (Scriptable) |

```
Browser / Scriptable
        │  JWT (Cognito)
        ▼
API Gateway HTTP API  ──►  Lambda commitfit-api  ──►  DynamoDB
        │                         │
        │                         └── Gemini (macro estimates)
        ▼
CloudFront + S3 (static site) ◄── Route 53 + ACM
```

---

## 1. IaC — AWS services (Terraform)

Remote state: S3 backend (`backend.tf`). Primary region: `ap-southeast-1` (ACM for CloudFront must live in `us-east-1`).

### 1.1 Static hosting & DNS

| Resource | File | Description |
|----------|------|-------------|
| **S3** `devopsminilab-site-storage` | `main.tf` | Stores the static site; **not public**; CloudFront reads via OAC only |
| **CloudFront** | `main.tf` | HTTPS CDN, alias `devopsminilab.site`, `PriceClass_100` |
| **CloudFront Function** | `main.tf` + `www/cf-rewrite-index.js` | Rewrites `/workout` → `/workout/index.html` |
| **ACM** | `main.tf` | Cert for `devopsminilab.site` + `*.devopsminilab.site` |
| **Route 53** | `main.tf` | Hosted zone + A alias → CloudFront |

### 1.2 Auth

| Resource | File | Description |
|----------|------|-------------|
| **Cognito User Pool** | `cognito.tf` | Email sign-up / sign-in with confirmation code |
| **Cognito App Client** | `cognito.tf` | SPA client (`generate_secret = false`), SRP + password + refresh |

### 1.3 API & data

| Resource | File | Description |
|----------|------|-------------|
| **API Gateway HTTP API** | `apigateway.tf` | `commitfit-api`, CORS for web + localhost |
| **JWT Authorizer** | `apigateway.tf` | All routes require `Authorization: Bearer <IdToken>` |
| **Lambda** `commitfit-api` | `lambda.tf` | Node.js 20, zip from `lambda/`, 25s timeout |
| **DynamoDB** `devopsminilab-commitfit` | `dynamodb.tf` | Single-table, PAY_PER_REQUEST |
| **IAM** | `lambda.tf` | Logs + DynamoDB Get/Put/Update/Delete/Query |
| **S3 object `config.js`** | `apigateway.tf` | Injects `COMMITFIT_API_BASE` + Cognito config into the frontend |

### 1.4 DynamoDB single-table

```
PK = USER#<cognitoSub>
SK =
  PROFILE              → calorie/protein goals, workout prefs
  EX#<exerciseId>      → exercise catalog
  N#<yyyy-mm-dd>#<id>  → meal
  PIN#<id>             → pinned meal template
  W#<yyyy-mm-dd>       → workout day (flags + sets[])
```

### 1.5 Variables & deploy

```bash
# Sensitive variable (Gemini)
export TF_VAR_gemini_api_key="..."
# optional: TF_VAR_gemini_model="gemini-2.0-flash-lite"

cd day14_miniproj
terraform init
terraform plan
terraform apply
```

Useful outputs: `website_url`, `api_endpoint`, `cognito_*`, `route53_nameservers` (point NS at your registrar).

## 2. App workflow — `www/`

Static frontend (HTML/CSS/JS), served via CloudFront.

### 2.1 Structure

| File | Responsibility |
|------|----------------|
| `index.html` + `script.js` + `style.css` | **Nutrition** page: yearly heatmap, meal log, AI estimate, pins |
| `workout/` | **Workout** page: exercise catalog, daily sets, flags (deload / stress / sleep) |
| `auth.js` | Sign in / Sign up / Confirm email / Sign out UI |
| `api.js` | Cognito + API Gateway calls (Bearer JWT, refresh token) |
| `demo.js` | Demo / local helpers |
| `cf-rewrite-index.js` | CloudFront Function source (not uploaded as a site asset) |
| `config.js` | **Generated by Terraform** — do not hand-edit or commit |

### 2.2 User flow (web)

1. Open `https://devopsminilab.site` → load `config.js` (API + Cognito).
2. **Sign up** → Cognito emails a code → **Confirm** → **Sign in**.
3. Tokens stored in `localStorage`; every API request sends `Authorization: Bearer <IdToken>`.
4. **Nutrition**
   - Yearly calorie heatmap by day.
   - Add / edit / delete meals per day.
   - **Estimate**: describe a meal → `POST /nutrition/estimate` (Gemini) → fill macro form.
   - **Pin**: save frequent meals as templates for quick reuse.
5. **Workout** (`/workout`)
   - Exercise catalog (defaults + custom).
   - Log sets by day; flags deload / highStress / poorSleep.
6. Profile: calorie / protein goals (header) synced via `GET/PUT /profile`.

### 2.3 Local development

CORS allows `http://localhost:3000`. Serve `www/` and ensure `config.js` exists (copy from Terraform outputs or serve after `apply`).

## 3. Lambda — what it handles

Entry: `lambda/index.js` → `handler` → `dispatch`.  
Runtime: Node.js 20 (AWS SDK v3 is available in the runtime); bundled dependency: `@google/genai`.

User id comes from JWT claim `sub` → `PK = USER#<sub>`.

### 3.1 API routes

| Method | Path | Behavior |
|--------|------|----------|
| GET/PUT | `/profile` | Read/write goals (calories, protein, hardSetTarget, plateIncrement) |
| GET/POST | `/exercises` | List / add exercises; empty catalog → materialize defaults |
| PUT/DELETE | `/exercises/{id}` | Update / delete an exercise |
| GET | `/nutrition?from=&to=` | List meals in a date range |
| POST | `/nutrition/{date}` | Add a meal |
| PUT/DELETE | `/nutrition/{date}/{id}` | Update / delete one meal |
| DELETE | `/nutrition/{date}` | Delete all meals for a day |
| POST | `/nutrition/estimate` | Gemini macro estimate from a description (`leanMealSchema.js`) |
| GET/POST | `/pins` | List / create meal pins |
| DELETE | `/pins/{id}` | Remove a pin |
| GET | `/workouts?from=&to=` | List workouts in a date range |
| GET/PUT/DELETE | `/workouts/{date}` | Get / upsert / delete a workout day |

### 3.2 Estimate (Gemini)

- Input: `description` (max 800 characters).
- Prompt: meal type, dish name, cooking/seasoning rules; macros = sum of items.
- Env: `GEMINI_API_KEY`, `GEMINI_MODEL` (default `gemini-2.0-flash-lite`).
- Without a key, estimate is disabled or fails depending on runtime behavior.

## 4. Scriptable — iPhone widget

File: `Scriptable/CommitFit.js`.

The [Scriptable](https://scriptable.app) iOS app runs JS outside Safari — used here as a **home-screen widget** against the same Cognito + API as the web app.

### 4.1 Setup

1. Copy `CommitFit.js` into the Scriptable app.
2. Adjust `CONFIG` if needed (`apiBase`, `clientId`, `region`, `siteUrl` — match Terraform outputs).
3. Run the script **once** → **Sign in** (same account as the website).
4. Tokens are stored in **Keychain** (not `localStorage`).
5. Add a Scriptable widget on the Home Screen → pick this script.

### 4.2 Behavior

| Mode | What it does |
|------|----------------|
| **Widget** (`runsInWidget`) | Refresh token if needed → `GET /profile` + today's `GET /nutrition` → draw Calories / Protein progress bars |
| **App (tap script)** | Menu: Sign in / Preview today / Sign out |
| Tap widget | Opens `siteUrl` (CommitFit web) |

The widget is **read-only** for today's nutrition progress; logging meals/workouts stays on the web.

## 6. Ops notes

- Change `www/` → `terraform apply` (S3 objects keyed by `etag`) + optionally invalidate CloudFront.
- Change `lambda/` → apply again (zip + `source_code_hash`).
- After apply, update Scriptable `CONFIG` if `api_endpoint` / `clientId` changed.
- Do not commit `.env`, `GEMINI_API_KEY`, or user tokens.
